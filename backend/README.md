# Сервер: напоминания в Telegram, перенос прогресса, рейтинг

Бот пишет каждому, кто подключил Telegram на сайте: сколько карточек пора повторить и какая тема проседает. Сайт держать открытым не нужно.

## Как это устроено
- `schema.sql` — отдельная схема `mathrepeat` в базе Supabase: `people` (один человек = один чат Telegram), `devices` (его браузеры, до 5) и `config` (настройки и секреты).
- `mathrepeat/index.ts` — одна Edge Function: вебхук бота, приём расписания и прогресса с сайта, рейтинг и ежечасная рассылка.
- Сайт отправляет на сервер только расписание (когда «созреет» каждая карточка), число неизученных карточек, название слабой лекции, серию дней, очки по дням и прогресс по карточкам (интервалы и даты, чтобы перенести его на другое устройство). Текста карточек и ответов на сервере нет.
- Перенос прогресса: у сервера есть номер версии; устройство с устаревшей версией сначала получает чужой прогресс, сливает его со своим (по каждой карточке побеждает более поздний ответ) и отправляет общий.
- Рейтинг: очки за последние 7 дней, имя берётся из Telegram, его можно сменить или скрыться во вкладке «Рейтинг».
- Когда человек отключает последнее устройство, его данные удаляются.
- Строка в базе появляется только после команды `/start` в боте, поэтому без Telegram сайт ничего никуда не отправляет.

## Запуск
1. Выполнить `schema.sql` в проекте Supabase.
2. Задеплоить функцию `mathrepeat` с выключенной проверкой JWT.
3. Создать бота в @BotFather, положить токен в `mathrepeat.config` и вызвать `/setup` (команды в конце `schema.sql`).
4. Включить расписание `cron.schedule` (там же).
5. Вписать адрес функции в `config.js` в поле `api`: `https://PROJECT_REF.supabase.co/functions/v1/mathrepeat`.

## Команды бота
`/status` — сколько карточек ждёт, `/top` — рейтинг группы, `/time` — время напоминания, `/stop` и `/on` — выключить и включить.

## Проверка
Сервер проверялся локально: PostgreSQL + Deno + подменённый Telegram, плюс сквозной тест с двумя браузерами (перенос прогресса и рейтинг).
